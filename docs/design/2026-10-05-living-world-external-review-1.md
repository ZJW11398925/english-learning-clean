> 2026-10-05 · 外审来源：用户转呈 · 本文 = 外审要点忠实记录 + 总控分析立场；裁决权在用户（设计主创）。

- 三设计成立点 + 四未闭合核心问题 + 两处规格未收干净 + 一处内容策略冲突。

## 三成立点（外审）

1. **特殊时刻机制是真正的发动机**（9/10）：「世界运行到值得用户在场的节点才停」使「用户看见的 ≠ 世界发生的全部」成为可能——信息差/传闻/多视角/可见性梯度皆由此派生。发动机不是事件池，是「运转→停止点」。
2. **可见性是叙事结构而非 UI 设置**：同一世界状态（暴雨→码头受损→铺子进水→Mrs. Fenwick 帮忙→Theo 事后听闻）在全知模式是一段世界演化，在全隐模式只是 Nell 信里一句 "The green door stuck again"——同一引擎两种产品。
3. **教学贴合解决学习覆盖**（撤销此前「不要让课程制造故事」的过绝对批评）：候选竞争（随机/剧情线/世界状态/教学贴合）+ 导演模式交用户，比「我要教邀请函→强制发生义卖」成熟。

## 四核心问题 + 总控分析

### Q1（HIGH）唯一动力源 vs 主动来信未闭合
- **外审**：§4.1「用户回信=唯一动力源」与 A3「笔友主动来信=定位灵魂缺口」存在张力——现所有「主动来信」在产品因果上仍是 user-triggered。需裁决：**A** 接受（世界只因用户回来而动，A3 重定义）；或 **B** 设计第二种启动条件——「上一次运转已产生一个未来可显现的特殊时刻，用户下次打开应用时才揭示」——世界不后台运行 ≠ 角色永远不能主动出现在收件箱。
- **总控分析**：**成立，且是 spec 内部两种思想未统一**——§3.3「你不在的世界积攒着等待」已隐含 B 的雏形，§4.1 又写「唯一动力源」。我倾向 **B**，并补一个定义：**「揭示」不算新运转**（揭示=完成上一次运转的呈现半；用户回信才是新发条）——因果链保持干净。裁决归用户。

### Q2 特殊时刻缺「交互义务」维度
- **外审**：四类时刻只定义了叙事重要性（停止点），没定义用户必须做什么。全部「停止等输入」→ 世界不断拿事件要求用户处理；全部「看完自动继续」→ 停止点失去意义。建议第二维三分法：**NOTICE（看见即可）/ RESPONSE（世界等你的通信）/ DIRECTION（世界允许你决定方向）**——这是世界节奏设计，非工程细节。例：中途便条=NOTICE（有时 RESPONSE）/ 回信=RESPONSE / 角色入场=NOTICE / 重大分岔=DIRECTION。
- **总控分析**：**成立，v2 必补**。三分法干净够小。补一个细化题：NOTICE 的「继续」语义（用户一个轻动作即续运转——非自动延迟，保住停止点意义）。

### Q3 三层记忆混入两个维度（总控自认概念错误）
- **外审**：hot/warm/cold 描述的是记忆温度（压缩程度/唤起概率），但「冷层=世界状态事实」把**记忆生命周期**与**世界状态生命周期**耦合了。例：去年 Nell 曾考虑卖铺最后没卖=冷记忆但**非**当前状态；今天屋顶损坏=滚烫记忆但**已是**当前世界事实。修正：事件史之下两个独立投影（memory temperature / current world state projection），同一事件可同时参与两者。
- **总控分析**：**完全成立——这是我写 v1 时的概念模型错误**。正交化后反而更顺：世界状态投影的生命周期（current/superseded）恰好接上主线-3 已落的 lore 事实 supersede 语义。v2 第三刀。

### Q4 世界越真实，课程覆盖越难（总控认为对产品定位最关键）
- **外审**：workplace English 目标在 Berrymoor 天然供给不足（那里高频的是 interpersonal/storytelling/礼貌请求，不是 sprint planning/deadline negotiation）——teaching-fit 硬注入多了 Berrymoor 变课程布景，不注入则目标长期欠覆盖。**解法：世界包声明 learning affordance（语言供给边界）**——Berrymoor 供给 informal correspondence/social pragmatics；Manchester 供给 workplace；Wellsby 供给 formal prose。教学系统据此知道「目标在本世界是否自然可供给」，不供给时建议换世界而非硬塞。**世界包从剧情内容包升格为语言环境包**。
- **总控分析**：**完全成立，且是四刀里挖出 spec 未竟价值的一刀**。affordance 还使多世界从「平行存档」升格为「语言环境的组合覆盖」——用户的学习目标组合决定世界组合；现役 93 个 R4 表达可按供给域聚类映射。

## 两处规格未收干净（外审，均成立）

1. **「只看她那边」**：单角色时代语言残留（多角色世界「她」是谁）→ 改「焦点角色/当前通信对象视角」。总控措辞漏洞。
2. **「首周/随后数周」**：真实时间措辞违反世界静止原则 → 改「第 N 次运转 / 前 N 封通信 / 第一个剧情阶段」。总控规格错误。

## 内容策略冲突（外审：必须裁一种）

- §7.2 四角色随后搬进 Berrymoor（**固定演员班底**模型） vs §9 四个背景是四个世界胚子（**世界原生角色**模型）——spec 同时保留两者。外审指出：Priya 是 Manchester 的 delivery manager，搬进 Berrymoor 必须是她人生的重大剧情变化，不能只是 onboarding 编排。
- **总控立场：裁世界原生模型**。理由：①现役角色内容深度绑定地方；②affordance 声明依赖世界原生性；③新手路径改「Nell 首发，其他**世界的门**随后可见/可去」而非「他们搬来」；跨世界访客保留为特殊剧情事件（Theo 来 Berrymoor 旅行=剧情级）。裁决归用户。
