## 1. 总架构——回合主干（D-A 混合；F9 裁死、F7 护栏）

**代码脊柱拥有回合主干，导演 agent 在决策点产出结构化调度决定**。裁死（F9）：导演 agent **不做 LLM tool-calling 自由循环**——每次调用＝组上下文＋任务说明→返回**结构化调度决定**（谁响应/顺序或并行/是否插世界事件/节奏参数）；「工具注册表」＝脊柱的受权执行面（§3），不是给 LLM 的工具箱。此裁同时消除「导演 agent 工具调用稳定性」进关键路径的风险。

**拍型（v0.2 立为一等参数）**：`open`（章首铺陈）/`advance`（世界推进，无你的输入）/`reply`（你的话或待落签驱动）。各拍型可见阶段不同（§12.1），因果不得倒置。

**脊柱回合管线（reply 型全链）**：你的输入（常开）→ ①意图解析（轻档）→ ②事件构造（代码）→ ③调度决策（导演 agent，结构化输出）→ ④角色响应（主角子体×k 并行）→ ⑤裁定（k 提案→δ，见 §1b）→ ⑥正史提交（canon_delta 三验）→ ⑦叙述渲染（叙述子体流式）→ ⑧停点判定 → 呈现，等你（或续拍）。`open`/`advance` 型：**只跳①**（无你的话可解——你的话只来自你）；**不跳④**——凡在场主角，其专属角色模型照常运转，各自决定此刻做什么、说什么（提案照走⑤裁定入 δ）；**③不退化**——导演 agent 在世界拍同样产出结构化调度决定（谁登场／何事逼近／节奏）。【DS-3，2026-10-15 用户照准】旧文「跳①④（无你的话可解、无角色须应——除非事件触及），③可退化为既定编排」废止——世界拍的舞台不空：无人替你想，但人人都自己在想。验收面：advance 拍正文里主角的言行必须可追溯到该主角模型当拍的提案（日志可查）——不允许叙述臂凭空写主角言行。

**续拍护栏（F7）**：`beat_complete` 后续拍**不得无界**——沿用已验护栏形态：单次驱动连拍上限（建议 3 拍，常量 `DRIVE_BEAT_CEILING`）＋单次驱动调用数上限（成本护栏，建议 12 次模型调用）；触顶＝有故之停（说明句入 note）。「一直写个没完」是已付过学费的事故形态，护栏从 POC 第一天在场。

**章级管线（导演位）**：章规划（导演 agent）→ 章间方向注入消化 → 章结算（幕外+整固）→ 下一章。

## 4. 沉浸呈现的停点判定
