## 1. 愿景

一款本地运行的活世界笔友应用：用户与一群共同生活在一个会动的世界里的角色通信——世界在用户每次回信后运转一步，事件发生、角色各过各的日子、彼此产生联系；教学不打扰地藏在信里、走向里、与「教我」里。**用户为世界而来，把英语学会了带走。**

产品本体约束（发散期纠偏沉淀，永为边界）：秒级反馈、即时进展、绝不以「等待」惩罚用户——**感知时间 ≠ 真实时间**。

## 2. 核心体验循环

```
读信（她在等你的回信） → 写信（自由表达·学习发生处） → 寄出（在途仪式·数十秒）
→ 世界运转（事件发生·你可选看见） → 走向（导演模式给方向/沉浸模式交给随机）
→ 停在下一个特殊时刻（多数时候=她的回信到达） → 循环
```

穿插其上：**揭示**（有时打开应用，一封早已积攒的信在等你——角色可以「主动」出现在收件箱，而世界从未后台运行，§4.1）；教学在任意环节以三层方式介入（§6）；学习闭环的杀手锏——**你用中文写给世界的意图，被教成英文，写进真正的信里，世界回应它**。

## 3. 世界模型

### 3.1 世界的构成
设定（时代/地点/基调）· 时间（世界内日历，随运转推进）· 角色阵容（随时出入场，出入场由世界叙事化——她搬来了/他去了远方）· 事件树（编年史：信件、事件、走向、出入场皆是节点）· 记忆与世界状态（§5）· 独立设置（§8）。

### 3.2 角色与关系
- 角色是世界内的演员：有自己的生活线（专属事件）、自己的记忆视角（**亲历的 vs 听闻的**——听闻可以有误差与延迟，传闻失真是天然剧情素材）、自己的通信节奏。
- **关系**：用户可预设（表亲/邻居/主顾），也可由共处事件自然演化。世界内角色彼此认识，同一事件在各自信中有各自折射。
- **互相通信**（用户开启后）：角色间有幕后往来，你偶尔听说；**传话玩法**——A 托你给 B 带句话，写一封转述信（天然的 paraphrase 学习场景）。
- **世界原生（v2 策略裁决）**：角色与世界深度绑定——Priya 是 Manchester 的人，不是可随处安放的「职场角色」。跨世界出现只能是**剧情级事件**（Theo 来 Berrymoor 旅行是他人生的大事），不是编排级的搬家。

### 3.3 多世界
- 用户可拥有多个世界，**互不影响**；一次只「住在」一个世界里（沉浸连续性）。
- 你不在的世界静止（回合制的自然推论），但可积攒「未来可显现的特殊时刻」——**这就是揭示的来源（v2 与 §4.1 统一）**：召回的钩子是「有一封信在等你」，不是惩罚。
- **组合覆盖（v2，随 affordance）**：多世界不止平行存档——用户的学习目标组合决定世界组合（§9.2）。

## 4. 运转引擎

### 4.1 动力：双启动条件（v2 裁决 B）
1. **发条（运转的唯一起点）**：用户回信寄出。世界的每次运转都由此启动——用户不来，世界不转。
2. **揭示（呈现半）**：一次运转可能在停止时留下「未来可显现的特殊时刻」（一封定会在某刻寄达的信、一件正在酝酿的事件）。它**静置**直到用户下次进入应用才揭示。**揭示不是新运转**——它只是把上一次运转欠你的呈现补给你；世界是否再转，仍只取决于你的回信。
> 于是「笔友主动来信」在产品因果上成立：她在你不在的时点「已经写了」（上次运转的产物），信一直在——**世界不后台运行 ≠ 角色永远不能主动出现在收件箱**（A3 兑现，张力消除）。

### 4.2 运转的七步序列（机制定义）
1. **发条**：用户回信寄出（§4.1——唯一运转起点）。
2. **时间推进**：世界内日历前进若干天/周（量级随事件密度，calibratable）。
3. **事件判定**：事件池中条件成熟者发生（§4.3）；活跃剧情线推进或收束。
4. **通信编排**：世界决定哪个角色此刻写信/寄便条/静默（角色近况 × 剧情相关性 × 上次来信间隔）。
5. **停止点判定**：到达本回合的特殊时刻（双维判定：内容类型 × 参与要求，§4.6；由事件戏剧重量决定，非机械一轮一停）。可同时留下未来可显现时刻（§4.1 揭示源）。
6. **呈现渲染**：按可见性设置（§4.5）渲染运转过程与结果。
7. **等待**：世界以「她在过日子等你的信」的静默存活——暂停即牵挂。

### 4.3 事件池
- **五类事件**：日常碎屑（轻·高频）/ 生活节点（中）/ 世界大事（重·低频）/ 角色专属（绑定单角色生活线）/ 联动事件（涉及多角色——互联的载体）。
- 事件来源：世界包自带池 + 运转中动态生成 + 剧情线衍生 + **教学贴合反向生成**（§6.4；受本世界语言供给边界约束，§9.2）。
- 每事件有：触发条件、戏剧重量、关联角色/剧情线、后续回响钩子（**随机负责发生，连续性负责让它显得像命运**——事件必须能进入记忆并获得回响，否则不生成）。

### 4.4 走向选项（导演模式核心）
- 世界运转到「可影响点」时生成 2–4 个走向候选，来源配比：
  - 随机池加权抽样（世界基调权重：平静/多事可设）；
  - **教学贴合候选**（按占比配额注入：常规三选一、高教学频率二乃至全——占比是用户设置；候选只在本世界供给域内生成，§9.2）；
  - 活跃剧情线的推进方向；
  - 导演模式下用户自由输入优先（**近全权**：可基本推世界到任何方向）。
- 沉浸模式不呈走向选项，世界偏随机运转（教学贴合仍以占比进入事件生成的暗中加权，同受供给边界约束）。

### 4.5 可见性（梯度）
全知（看见运转全程）/ **焦点角色视角**（v2 措辞修正：只看当前通信对象那边）/ 只看与我相关 / 全隐（只见结果——回信到达时的戏剧性惊喜）。同一引擎，渲染开关——**同一世界状态，不同可见性产出不同的产品体验**（外审成立点二）。

### 4.6 特殊时刻协议（v2 新增，外审 Q2）
**双维定义**：内容类型 × **参与要求**。参与要求只有三种语义：

| 参与要求 | 语义 | 交互 |
|---|---|---|
| **NOTICE** | 看见即可 | 一个轻「继续」动作（用户点击，非自动延迟——保住停止点意义又不构成回应负担）即续运转 |
| **RESPONSE** | 世界在等你的通信 | 世界保持等待，直至你的回信（发条） |
| **DIRECTION** | 世界在此允许你决定方向 | 呈走向选项（导演模式）；沉浸模式由设置决定走向来源 |

内容类型 × 参与要求的典型映射（非硬编码，运转编排可调）：

| 时刻 | 常态参与要求 | 可变 |
|---|---|---|
| 回信到达 | RESPONSE | — |
| 中途便条 | NOTICE | 偶尔 RESPONSE（她在等你一句话） |
| 角色出入场 | NOTICE | — |
| 事件爆发 | DIRECTION 或 RESPONSE | 按戏剧重量 |

> 这是世界的**节奏设计**：NOTICE 让世界「有话说但不索取」，RESPONSE 制造牵挂，DIRECTION 交出权柄——三者配比即世界的呼吸感（calibratable，随密度实测一起调）。

### 4.7 密度
运转密度（每步事件量/时间推进量）**不做先验定值**——calibratable，用户实测亲调（用户裁决）。NOTICE/RESPONSE/DIRECTION 配比同此。

## 5. 记忆系统与世界状态（v2 正交化）

### 5.1 双投影总纲（v2 核心修正，外审 Q3）
事件史之下有**两个独立的投影**，同一事件可同时参与两者：

```
EVENT HISTORY ──→ memory temperature（记忆温度：它被怎样记住）
EVENT HISTORY ──→ current world state projection（世界状态投影：现在仍为真）
```

**记忆生命周期与世界状态生命周期解耦**：「记得很久的事」≠「现在仍为真的事」——去年 Nell 曾考虑卖铺而没卖（冷记忆，但非当前状态）；今天屋顶损坏（滚烫记忆，但已是当前世界事实）。

### 5.2 记忆温度三层
- **滚烫层**：最近 N 个运转回合的事件，细节完整（谁/何时/原话）。
- **温层**：超龄事件压缩为一两句摘要（运转后自动降级压缩）。
- **冷层**：被反复唤起或剧情收束后的事件，压缩为稳定的长期记忆要点——**只描述记忆，不再是世界状态（v2）**。
- **遗忘**：温层事件长期无唤起（不挂任何剧情线、不被引用）则降权至「不可唤起」——数据仍在（本地全文可检索旧信），但不再进入生成上下文。**记不清无关旧事是特性，像人。**

### 5.3 世界状态投影
- 从事件史独立投影的**当前事实集**（「学徒已离开」「屋顶当前损坏」「Nell 仍拥有装订铺」）。
- **自己的生命周期**：current → superseded（被后续事实覆盖）——与既有 lore 事实语义天然衔接。
- 世界现状摘要（投影的压缩形态）恒定地小，是每封信上下文的常驻底座。

### 5.4 注意力（唤起机制）
- **三根指针**决定唤起：当前写信的角色（她的视角记忆优先）· 活跃剧情线（线上事件加权）· 用户近信内容（语义相关）。
- 唤起沿**事件关联网**扩散一层（共现即相连）。
- **剧情线**是记忆的一等挂架：线上记忆保持唤起优先；线收束，整线沉降为一条冷层记忆要点（其状态后果入世界状态投影）。
- **引用强化记忆**：被提起多次的事件记忆权重升——重要的事记得牢，因为它在剧情里被反复唤起。

### 5.5 token 预算
- 世界级「记忆预算」设置（每封信上下文 token 上限）。
- **分层装配**：人设（小而恒）→ 世界状态投影摘要（恒小）→ 活跃剧情线摘要 → 唤起事件（按相关性排序填入预算，紧则截断保头部）。
- 记忆压缩比（细节保留度）为用户旋钮；消耗可见（token 仪表）。

## 6. 教学系统咬合

### 6.1 三根天线
1. **纠错天线**（既有 detector 链）：用户英文信中的错误。
2. **意图天线**：用户以母语表达的任何意图（导演走向输入、中文信内容）→ 判定「这句话值不值得此时学它的英文」。母语意图 = 真实表达需求的完美采样。
3. **索取天线**：「教我」入口——回信中的词/句/表达、自己中文信的某句、世界事件卡的说法，一键进教学。

### 6.2 触发决策器（五砝码）
表达价值（高频/可迁移）· 距离（近发展区）· 用户旋钮（三档档位=自动层松紧）· 剧情重量（重要句值得教，学了马上用）· 当下节拍（见延迟教学）。

### 6.3 三层并存（一本预算账）
- **自动层**：底线监听一切文本，达阈值触发。
- **潜入层**：不出手，在回信中轻标记「值得学」的表达——可见但不打扰。
- **主动层**：「教我」。主动密集时自动层识趣降频——教学预算全局一本账。

### 6.4 教学贴合与供给约束（v2 随 affordance 强化）
教学为世界让路为常态；反向生成走**可见的贴合选项**：走向候选中按用户设置的占比注入教学贴合项。**贴合候选只在本世界的语言供给域（§9.2）内生成**——超出供给域的学习目标不硬塞，改由教学系统提示「另一个世界能自然练到它」（§9.2 组合覆盖）。**贴合标注与否是设置项**（标注=知情选择；不标=学习藏在兴趣里）。

### 6.5 延迟教学
剧情高潮处只开潜入层；高潮过后教学跟进。保情绪增强记忆的红利，不打断沉浸。

### 6.6 学习闭环（杀手锏）
中文意图 → 教学教英文 → 学到的英文写进真正的信寄出 → 世界回应它。学习获得即时世界性回报。

## 7. 信息架构

### 7.1 IA 翻转（用户裁决）
**世界是第一公民**：先有世界，再有角色；角色共享一个事件树；信件是世界运转的输出。

### 7.2 新手路径（v2 修正：世界原生 + 计数化时间）
首开三步内进入预制世界 **Berrymoor**——Nell 的第一封信已到，你的第一个动作就是回信（核心循环零门槛启动）。教学在头三封信内以潜入层首次现身；第一个世界事件在**前若干次运转**内到来，世界感建立。**其余世界的门随进度可见**（Theo 的 Greyfield、Priya 的 Manchester、Evelyn 的 Wellsby——不是他们搬来，是「世界架」上亮起新的门）；高级能力（自建世界/导演模式/多世界）不隐藏、不打扰，稳定使用后自然揭示。时间量纲一律用**运转次数/通信封数/剧情阶段**（世界不跟真实时间走）。

### 7.3 世界创建（三档）
1. **官方世界直接用**（默认）。
2. **模板分叉**：复制官方世界并个性化——「平行世界」。
3. **从零自建**（高级）：写世界设定 → 选/建角色 → 定基调与事件倾向 → **声明语言供给域（v2，可自选）**。

### 7.4 多世界 UI
- **案头 = 当前世界的收件箱**（沉浸连续性，一次住一个世界）。
- **世界架**：世界切换面（每世界一格，有待读信角标；别的世界静置但积攒的等待可见——揭示的入口）。
- 世界指示器：当前世界名 + 世界内时间/天气的静默暗示。

### 7.5 角色出入场
随时加入/删除角色；**出入场由世界叙事化**。删除与叙事留痕并存（本地应用，无隐私语义——用户裁决）。

## 8. 设置面全景

**世界级**（每世界独立）：模式（导演/沉浸）· 可见性（四档梯度）· 教学贴合占比 · 贴合标注开关 · 世界基调（平静↔多事）· 记忆预算与压缩比 ·（实测后开放）运转密度与时刻配比。
**全局**：教学三档与频率旋钮（现役面）·「教我」入口显隐 · 主题/排印等。
→ 落位：现役设置页分组 IA 的世界组扩展。

## 9. 世界包与语言供给（v2 升格）

### 9.1 世界包构成
世界设定 + 初始阵容 + 事件池（日常/季度/节点三层）+ 初始剧情线 + 教学贴合素材映射 + **语言供给声明（v2）**。

### 9.2 语言供给（learning affordance，外审 Q4 采纳）
- 每世界包声明**本世界自然高频的语言需求域**——不是课程表，是环境的供给面：
  - **Berrymoor**：interpersonal · storytelling · everyday requests · social pragmatics · informal correspondence
  - **Manchester（Priya）**：workplace communication · deadlines · project updates · negotiation · polite disagreement
