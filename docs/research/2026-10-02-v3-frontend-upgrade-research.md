## 0. 一句话结论

navdock 的问题不是「丑」，是**信息密度与质感双低**——三条 12.5px 文字链落在与页面
同色（`--paper`）的一条底带上，当前态只是一根 6px 偏移的墨蓝下划线，与正文的文字
链接无法区分「导航」与「动作」两种语义；成熟应用的底导航在同样约束下（零大圆角、
零色块可用）仍有四件武器没用上：**墨线图标、当前态的材质差（落墨/纸片浮起）、
高度与安全区的从容、桌面档的左岸形态**。dock 的问题是**形态唯一样态**——常驻
109px 垫板 + 2 行不增高的 textarea，写作、等待、阅读三个状态共享同一形态，没有
「收起」，没有「写作沉浸」，长信在 2 行小井里滚动（实测 7 行文本挤压滚动）。成熟
范式给出的答案是三态分离：**收起 = 触发条（一行）、聚焦 = 自动增高稿纸、深写 =
近全屏信纸写作态**——三者都能在纸墨语汇内成立，无需豁免形态法则；推荐的组合是
navdock N-A（墨线图标 + 落墨当前态）+ dock D-B（触发条 + 信纸全幅写作态）。

### 1.2 双档口径与一个方法学发现

- Playwright MCP 默认上下文带**触屏仿真**（实测 `maxTouchPoints=5`、
  `matchMedia('(hover: none)')===true`、`pointer: coarse`）——首遍「1280 桌面」
  实际渲染的是触屏形态分支（词卡 bottom sheet、沓容器 z9）。发现后补开
  **干净无触上下文**（`hasTouch:false, isMobile:false`）重跑桌面档。
  **本报告桌面读数均以干净上下文为准；触屏读数以触屏仿真上下文为准。**
  这个坑值得进 v3 刀的验收程序：走查双档必须显式声明 hover/pointer 形态，不能
  只看视口宽度。
- 键盘协同无法在 Playwright 里拉真软键盘，用**视口压缩模拟**
  （390×844 → 390×450，等价 `interactive-widget=resizes-content` 生效后的布局
  视口；该 viewport meta 键现役已设，见 9.6）。

### 2.2 navdock 逐项诊断

- **N1 语义混叠**：navdock 的「案头/温故/抽屉」与正文里成打的墨蓝下划线文字链
  （「去聊一句」「翻看以前的信」「← 回案头」）用同一套视觉语汇（小字 + 下划线）。
  用户扫一眼无法先验地区分「这是三个房间」和「这是一个动作」。导航是常驻骨架，
  应有自己的体量与材质，现在它比一条正文链接还轻。
- **N2 当前态过弱**：当前态 = 字重 600 + 一根 accent 短下划线。实测在温故屏上，
  顶部的节签（今日/方向/档案，同为文字 + 下划线）与底部 navdock 形成两排几乎
  同形的文字链——「我在哪个房间」的答案在屏幕上出现两次却都不响。iOS/Material
  的共识是当前态用**双通道**表达（图标形变 + 标签色重，或衬底 + 色重），单靠
  一根 1px 线是最低档。
- **N3 材质零差**：navdock bg = `--paper`，与温故/抽屉的正文底同色——底带只靠
  一根发丝线从页面里「分」出来，没有「件」的存在感。对比：dock 用了
  `--paper-high` + 向上承影（8.2.2② 的垫板层设计），同一屏上 dock 是件、
  navdock 是印在纸上的字。信件隐喻里它本该是**案头的沿口/镇纸条**。
- **N4 触感缺失**：按压反馈 = translateY(1px) + state-layer 雾（现役 ③ 契约），
  hover 变色。没有切换时刻——点温故，三个字各自换了个下划线，屏幕上没有任何
  「发生了什么」的物理事件（对照：简报 §5 每个关键事件都有纸事件）。成熟 tab bar
  的切换感来自图标形变/衬底滑动，此处为零。
- **N5 令牌账实差 3px（瑕疵级 bug）**：`--navdock-h: 54px` 与实测 57 不符
  （6px 上 padding + 44px item + 6px 下 padding + 1px 边框），导致 dock 以
  `bottom: 54px` 落位时盖住 navdock 顶发丝线（实测 navBorderCovered=true）。
  v3-2 刚立的 `--navdock-clearance` 令牌账是对的，但源值本身错了 3px，且无人
  消费真实高度。修法见 §4.1 共同基座。
- **N6 桌面档没有自己的答案**：≥900px 后 navdock 三项收拢居中（min-width 132px，
  gap 48）——把手机底栏原样搬到 1240px 宽的桌面上，下方 57px 高的一条带子上
  三个词，而右侧 240px 边注栏只有一行日期 + 一根界尺线（`aria-hidden`，实测
  无任何导航职责）。桌面成熟的导航位是左岸（Linear/Things/Bear/Mail 全族），
  现役构图把最空的区域留给装饰、最挤的区域留给导航。
- **N7 点按靶与安全区是对的**（先记下来，升级不许丢）：44px 高、`--safe-bottom`
  垫底、门厅让位、z 6 低于一切浮层——这四件是现役底子。

### 2.3 dock 逐项诊断

- **D1 无法收起（用户点名硬伤）**：`.dock` 是 fixed 常驻件，DOM 上没有收起态——
  任何状态（阅读、等回信、看批注卡）都承受 109px 垫板。桌面 20.4%、移动 19.3%、
  键盘压下 36.1% 的屏幕是「可能要写信」的永久税。
- **D2 写作井不增高**：textarea rows=2 固定，实测塞 7 行文本出现内滚动条
  （DD5 截图）。现代输入框的底线（iMessage/Telegram/Day One 全族）是自动增高，
  本应用是**写信应用**，写作件反而是全应用最不写作的形态。长信 = 在 84px 高的
  井底摸黑。
- **D3 三态同形**：阅读时、等待回信时（typing 指示行在信流里，dock 纹丝不动）、
  写作时，dock 长得一模一样。唯一的状态应答是聚焦微起 2px + 左墨线（8.2.2②，
  实测 transform matrix(…,-2)、::before opacity 0.5——手感是对的，幅度不够
  承担「我在写信」的状态宣告）。
- **D4 聚焦环过重**：程序聚焦（寄出后焦点留守 textarea）后 `:focus-visible`
  环常亮（DD6 截图：输入框一圈深色实线环）——纸面语汇里最「浏览器默认」的
  一笔，压过精心做的左墨线。键盘可达性要保，但环的形（现役环 vs 自定义
  发丝焦点环）值得在 v3 重铸。
- **D5 键盘压下时 navdock 白吃 57px**：写作时底部自上而下是 [dock 109]
  [navdock 57] [键盘]——navdock 在写作场景零职责却排第二高。成熟做法是写作态
  收导航（全页让位规则现成：门厅/信档已经这么做了）。
- **D6 移动端死区**：flow 底补 310px 按桌面「dock 109 + 呼吸 + 追底余量」手写，
  移动端滚到底出现约 200px 无物之纸（实测 last 480 vs dock 681）。「信流摊在
  案头」的末端变成空白桌布。
- **D7 寄出反馈对了**（保持）：寄出一瞬 `stamp-press` 盖戳（app.js:2460/
  2537，scale .96→1 唯一 overshoot）+ 信落信流 + 焦点留守续写——这条链是
  现役好手艺，v3 写作态重铸时原样保留。
- **D8 批注开着时的指路行孤立**：`#reply-guide`（「批注开着——回应写在上面
  那张…」）是 dock 里的一行 meta 文字，教学时刻开着时 dock 其余部分照旧——
  「回应该往哪写」只靠一句话说，形态上没有把「回应位」让出来。低频路径，v3
  写作态（触发条）下这句话可以升级为触发条自身的文案态。

### 2.4 触屏可发现性附测

最新信词带（8.2.2④(a)，触屏档限定）实测：一封 39 词回信全部词带灰底
（`--accent-soft` 12%）。逐词灰盒连成片后读感是「碎」（M0/d2 截图），且
「可查」的边际信息为零——39 个词几乎都不可查（P1-2 已登记词表覆盖率 1/36）。
这是**设计正确、参数过宽**的典型：衰减律缺失。已入 §5 机会清单 O4。

### 2.5 现役做对了的（升级红线：不许丢）

1. 门厅/全页 navdock 让位 + Esc 逐层退栈（⑩）——v3 任何新形态都必须接进这套
   让位/退栈语义，不是绕开它。
2. dock 垫板层的材质设计（8.2.2②：paper-high + 上缘发丝线 + 向上承影 +
   聚焦微起 2px）——「垫板被手压起」是对的隐喻，v3 把它放大而不是换掉。
3. 触感第一律（≤100ms 反馈）与 reduced-motion 双面降级——新动效全部继承。
4. `--navdock-clearance` 令牌账（v3-2）——一切固定底具补偿带的算术底数，
   N5 的修法就在这个令牌上，不在散落手写。
5. 寄出盖戳 + 信落信流 + 焦点留守（D7）。
6. 点按靶 44px / `--safe-bottom` / hover 半区 `@media (hover:hover)` 包裹。

## 3. 范式研究 B（成熟形态库）

> 每范式：形态描述 → 适用条件 → 与信件隐喻的相容性。取材 = iOS HIG（tab bar /
> keyboard）/ Material 3 navigation bar / macOS 三栏应用（Mail·Things·Bear·
> Linear）/ 优质 Web（Linear、Notion、Kindle web、Day One、Telegram Web）/ 日记
> 应用（Day One、Journey）的公共形态知识；不引具体版本号，只固化形态判断。

### 3.1 底部导航的成熟形态

- **P1 图标在上 + 文字标签在下（iOS tab bar 形）**：49pt 高，图标 24–25pt，
  标签 10pt。图标让导航在扫视时「先认形后认字」，文字保语义（无障碍与陌生
  用户）。适用：3–5 个平级目的地。本应用恰 3 项。**相容性：高**——墨线图标
  （#22 语汇）天然是「界尺描形」，与「动作=文字链接」不冲突，因为导航不是
  动作是地点；需动 #18 契约「禁止变体：图标」条款（显式修订 + 用户首验）。
- **P2 当前态双通道（形变 + 色重）**：iOS = 图标 outline→filled 切换 + 标签
  色重；Material 3 = active indicator（衬底胶囊）+ 图标变体。核心洞见：当前态
  要让**余光**可辨。**相容性：极高，且有一层隐喻红利**——「描形 → 实墨」正是
  简报 T1-3「墨水物理」（`--ink-ghost → --ink`）的静态版：当前房间是「落了墨」
  的。填充过渡走 ink-wash（opacity 恒慢 1.3×），切换 = 一次落墨事件。
- **P3 材质分层底带（浮起件）**：成熟 tab bar 从不是「印在背景上的一行字」，
  而是一块有材质的件（iOS 的材质栏 / Material surface + elevation）。在本仓
  语汇内 = navdock 升为 `--paper-high` 顶纸垫条（或 `--paper-2`）+ 顶发丝线，
  与 dock 的垫板语言对齐；禁止毛玻璃（T3 死刑），纸色差即可。**相容性：高**，
  成本最低的一件。
- **P4 滚动隐现（scroll-to-hide）**：向下滚动阅读时底导航滑出屏底，回滚/触底
  复位（Safari 底栏、很多阅读器）。适用：内容沉浸优先的屏。**相容性：中**——
  「常驻 dock」是 ⑩ 宪法的层类型之一，隐现 = 常驻语义修订；且信流不长时收益
  小。列为 D-C 方案的组成件而非必选。
- **P5 安全区从容**：成熟底栏把 `safe-area` 垫进自身 padding（现役已对），
  高度留呼吸（iOS 49pt 内容高 + 安全区）。现役 54/57 偏紧但不失格；P1 升级后
  建议 60px 内容高。
- **P6 桌面左岸（left rail）**：≥900px 的成熟应用几乎不用底导航（Linear/
  Things/Bear/Mail/Notion 全是左栏），底栏在宽屏上是手机范式错置。本仓桌面
  已有边注栏席位（208/240px）但只放日期。**相容性：高**——边注栏改名「案头
  侧栏」承接三空间导航（文字 + 墨点/图标），navdock 桌面档退役；`--shell-w`
  与 `--navdock-clearance` 消费面按 9.6 分档。这是「敢升级」的一件，涉及
  断点契约修订。
- **P7 徽标/计数（badge）**：tab 上挂真实状态数（未读/待办）。本仓有天然对应：
  温故的到期数、沓的封数。朱砂纪律（只盖真实事件）反而支持它——badge 是真实
  事件计数。v3 可后置，不进首刀。

### 3.2 输入区的成熟范式

- **Q1 双态输入（触发条 ⇄ 展开条）**：iMessage/Telegram/微信的常态——收起时
  是一根单行触发条（占 ~56px 含安全区），聚焦后升起多行并自动增高到阈值
  （通常 5 行/屏幕 1/3），超过则内滚动。**核心是「写信的意愿」决定高度**。
  适用：本应用一切场景。**相容性：极高**——触发条可做「笔搁」：一根放笔的
  细木条（发丝线 + 一行 placeholder），隐喻直给。
- **Q2 自动增高（autosize）**：输入时 textarea 随内容长高（scrollHeight 驱动
  或 `field-sizing: grow`），封顶后内滚。这是 Q1 的机制件，纯 CSS/JS 可达，
  工程上是一处 `input` 监听 + 高度钳制。
- **Q3 全屏写作态（compose sheet）**：邮件应用（iOS Mail、Spark）与日记应用
  （Day One）的「写」不是内联条而是**一张全屏/近全屏的新信纸**：顶部收起钮 +
  日期，正文区吃满余高，底部寄出。触发方式 = 点触发条或专门「写」动作；退出 =
  收起钮 / 下滑 / Esc，草稿保留。**相容性：极高且是本应用的题眼**——简报 T1-1
  的排印骨架（dateline/称呼/正文/落款）可以直接长在写作态里：**写信时看到的
  就是信的样子**（现役写作时看到的是一个表单控件）。这是「全面升级」最值得
  花钱的一件。
- **Q4 草稿保留**：退出写作态不清空；切换会话/角色时按会话分桶（Telegram/
  微信皆此）。本仓对应 = 按角色分桶（`draft:<character_id>`），信封沓切换时
  草稿各自待着。轻量实现 = sessionStorage；信件隐喻支持它（写了没寄的信压在
  笔搁下）。
- **Q5 键盘协同**：iOS 键盘跟随输入框；`interactive-widget=resizes-content`
  （现役已设）让布局视口收缩、fixed 底具贴键盘上沿；成熟应用在键盘压下时
  收走一切非写作件（P5+D5 结论：写作态 navdock 让位）。
- **Q6 防误触**：滚动时输入条保持不动（不跟随滚动抖动）；按压目标是触发条
  整条而非只有 placeholder 文字；展开态有明确的收起钮。现役 focus-within
  微起已防了「误碰即升起」的惊跳（2px 是预告不是展开）。
- **Q7 等待态的输入纪律**：回信在途时成熟应用不锁输入（可继续写下一封）但
  给出明确的在途指示。现役：typing 行在信流、dock 不变——可继续写是对的，
  保持；触发条形态下在途指示可上浮为触发条右侧一行弱墨小字（「等回信——笔友
  把灯留着」现成文案）。

- **新增令牌（走 ② 表登记）**：`--dock-trigger-h: 44px`（触发条内容高）、

  `--ease-press`；位移 4–12px 封顶；零常驻循环；reduced-motion 直切。
- **z 序**：触发条/展开态 dock 沿用 z 8；写作态面板如果做全页（D-B），按 ⑩
  是**全页成员**（文档流整页 + navdock 让位），不新增层类型——这是 D-B 工程上
  最省的路径（复用门厅让位机制与 Esc 退栈语义：Esc = 收起写作态）。

  - `desk`（案头）：桌面横线（x3–x17, y15）+ 桌上立信（rect x5 y4 w10 h9）+

  - `drawer`（抽屉）：抽屉立面（rect x4 y6 w12 h9）+ 拉手短线（x9–x11, y10.5）

  - 三枚均以 1.5px 描形为默认态；当前态填充 = 同 path 以 `fill: currentColor`

    opacity `--dur-note` 260ms × `--ease-paper`（墨渗入纸），transform 无。
- **语义不变项**：空间名（案头/温故/抽屉）、dock ≤5 红线、门厅让位、

```

状态矩阵：

| 态 | 形态 | 触发 | 退出 |
|---|---|---|---|
| 收起 | 44px 触发条（paper-high 垫板同现役材质） | 默认 | 点按 / Tab 到位 / 有草稿时点草稿点 |

草稿墨点 = 静态 4px 圆点（`--ink-soft`）——**圆点属「印记」族，仅真实事件
（未寄草稿）所有，不违朱砂纪律（它是墨不是朱砂）**。

工程落点：`app.js` textarea `input` 监听 autosize（`scrollHeight` 钳制，
`field-sizing: grow` 作渐进增强）+ `.dock` 收起态类 + 失焦逻辑；`index.html`
触发条结构（textarea 与触发条文案同 `.dock-row` 双态渲染）；`.flow` 底补从
310px 改 `calc(var(--navdock-clearance) + var(--dock-trigger-h) + var(--sp-6))`
（死区 D6 顺带清账）。

优点：直接回应用户硬伤（可收起）；实现面小（无新层型、无路由变化）；草稿
语义自然。缺点：长信写作仍是「条」——没有为「写一封长信」准备形态；写作沉浸
感只到 160px 封顶。

#### D-B「信纸全幅写作态」——触发条 + 近全屏新信纸（主推）

形态图（移动 390）：

```
收起态（同 D-A 触发条，44px）:
  ╞═══════════════════════════════╡
   提笔 · 今日如何？          寄出 →
  ╞═══════════════════════════════╡
       案头        温故        抽屉

写作态（点触发条升起——navdock 让位，占满 --shell-w 全高）:
┌─────────────────────────────────┐
│ ↑ 收起            2026 · 10 · 02 │ ← 顶行：收起链 + dateline（等宽旧式数字）
│                                  │
│ 致 Nell Alder，                    │ ← 称呼位（弱墨，只读；来自 /api/partner）
│                                  │
│ ▏今日如何？                       │ ← 稿纸区：基线网格横线（--baseline 32 周期）
│ ▏                                │    自动增高，吃满顶行与底行之间的余高
│ ▏                                │
│                                  │
│                     寄出 →        │ ← 底行：寄出链（右齐，同现役语汇）
└─────────────────────────────────┘
```

桌面 1280 写作态：同一面板限宽 `--shell-w`（信纸居中在桌布上），顶行/底行同构，
稿纸区两侧露桌布——「抽出一张新信纸摊在案头中央」。称呼位/落款预览是排印骨架
的静态部分（T1-1）：稿纸下方恒有一行右齐弱墨「此致」位占位不渲染文字（落款
仍是回信的「你」——落款由系统在信落流时排，写作时不伪装手迹）。

状态矩阵：

| 态 | 载体 | 关键面 |
|---|---|---|
| 收起 | 触发条（同 D-A） | 默认；有草稿时右端墨点 |
| 写作 | 全页面板（`.dock--compose`，文档流 fixed 全高、`--shell-w` 限宽） | navdock `[hidden]`（让位，同门厅）；焦点入 textarea；dateline = 本机日期（mono micro 旧式数字——现役 marginalia 同源）；称呼位 = 当前角色名 |
| 写作·超长 | 稿纸区内部滚动 | 基线网格 background-position 锁首行（字落在线上，简报 3b） |
| 草稿 | `sessionStorage["draft:<character_id>"]`，input 即存 | 切空间/切角色各自分桶；寄出即清；收起不清 |
| 等回信 | 收起触发条右侧弱墨小字（同 D-A） | 写作态内不阻塞（可继续写下一段） |
| 批注开着 | 收起态触发条文案 = 指路行原文 | 点触发条 = 对批注回应（路由不变，语义照旧） |
| 禁用 | 寄出链 disabled（发送中） | 同 D-A |
| Esc / 「↑ 收起」 / 下滑（移动，|dy|>|dx| 且 >60px） | 退栈收起（⑩ Esc 语义：写作态 = 全页层的收起） | 草稿保留 |

动效（「纸先落、墨后渗」的正场）：
- 升起：面板 transform translateY(14px→0) 280ms `--ease-paper` + opacity
  364ms 恒慢；触发条同帧压暗为面板底影；navdock fold 200ms `--ease-exit`
  （同 envsel--fold 语族）。
- 落下：200ms `--ease-exit` + ink-wash reverse；信流底补从触发条账重算（无
  跳变，因 flow 底补按收起态常备）。
- 寄出：**现役链原样保留**——面板收起与信落信流同帧编排（先信落 paper-drop
  280ms，面板随 opacity 收，恒慢），postmark stamp-press 120ms 不动。

工程落点：
- `index.html`：`.dock` 内增两态结构（触发条行 + 写作态面板），同一 form
  `#send` 的 textarea 为唯一真源（触发条是它的投影文案，不做双 textarea）。
- `screens.css`：`.dock--compose` 全页态 + 基线稿纸背景（复用现役稿纸线语汇，
  `--baseline` 周期）；`@media (max-height: 520px)` 横屏矮视口降级为 D-A
  展开态（全幅写作在矮视口得不偿失——诚实降级）。
- `app.js`：compose 状态机（open/close/draft 三面 ~80 行）+ Esc 接现役退栈
  （wordCardOpen 裁决之后、容器退栈之前的一层）+ `sessionStorage` 草稿 +
  沓切换时草稿桶切换。
- ⑩ 层级宪法：增一行「写作态（.dock--compose）= 全页成员，navdock 让位，
  Esc 收起」——不新增层类型，零 z 序表改动（fixed 全页沿用 dock z 8 之上
  遮挡关系已被 ⑩ 全页语义覆盖）。
- `interactive-widget=resizes-content` 现役已设，键盘压下时面板自然贴键盘；
  不引 visualViewport 监听（登记 Revisit：iOS Safari `resizes-content` 缺失
  引擎的回退面）。

优点：写作终于有「一张信纸」的形态尊严；排印骨架（dateline/称呼）首次在
写作时在场；键盘压下时 navdock 白吃 57px 的问题（D5）被让位规则自然消灭；
触发条把常驻税从 109px 降到 ~52px（移动端阅读区 +57px）；草稿分桶支持多
角色并行写信。缺点：交互面新增一个状态（用户要学一次「点一下开始写」）；
矮视口降级档需要真实设备验证；「收起后写信入口变得不明显」的可发现性风险
——对策：触发条文案永显「提笔 · 今日如何？」且空厅引导句点击即开写作态
（见 O1）。

**需用户豁免/显式修订清单（D-B）**：
1. 「写信区常驻全形」现役规则（8.2.2）修订为「触发条常驻 + 写作态按需」
   ——形态级修订，用户首验。
2. 写作态引入「全页成员」新枚举（⑩ 登记行）——宪法登记，非豁免。
3. 草稿分桶是新行为（无害，隐私面零外发，sessionStorage 进程级）——登记即可。

#### D-C「墨盒随卷」——滚动协同收缩（激进备选）

形态图：

```
阅读中（向下滚）:                    静止 2s / 回滚 / 点按:
╞═══════════════════════╡            ╞═══════════════════════╡
      ◦ 提笔                      ⇢     今日如何？          寄出 →
（收缩为一枚 28px 墨签）               （复位为触发条）
╞═══════════════════════╡            ╞═══════════════════════╡

向下滚动阅读时触发条进一步收缩为一枚右下角墨签（28px 圆less 方签，radius ≤2px，
`--paper-high` + 发丝边 + soft 阴影，含 4px 墨点 + 「提笔」二字 micro）；停止

收起」，在 D-B 之上加收缩态是增量，反向不然。

#### dock 必答三问的答复

1. **收起/展开机制**：收起形态 = 44px 触发条（笔搁：placeholder + 寄出链）；
   唤起 = 点触发条 / 空厅引导句 / 温故「去聊一句」落位后自动开写作态；写信
   焦点流不丢 = 寄出后焦点回触发条（再点即回写作态），草稿按角色分桶常在。
2. **聚焦态写作沉浸**：D-B 近全屏信纸（navdock 让位、排印骨架在场、稿纸基线
   网格、矮视口自动降级为展开条）；D-A 封顶为 160px 自动增高条。
3. **移动端键盘协同**：`interactive-widget=resizes-content`（现役）+ 写作态
   navdock 让位（键盘压下时家具只剩面板自身）+ 收起钮常在（不依赖下滑手势
   作为唯一出口）+ 防误触（触发条整条为点靶 ≥44px；展开不以 hover 类信号
   触发）。

### 4.3 推荐组合与理由

- **navdock = N-A「落墨页签」**：三案中唯一「小刀 immediate、隐喻白送、零
  豁免」的组合点——图标给形、落墨给态、顶纸垫条给材质；N-B 的纸片动效好看
  但 JS 量位与拥挤风险不值首刀下注；N-C 桌面左岸方向正确但断点契约面大，
  建议立为独立刀与用户裁决后再动。
- **dock = D-B「信纸全幅写作态」**：用户要「全面升级」，D-A 只是把税降了，
  D-B 把「写」变成产品的主角形态——排印骨架在写作时在场是全应用唯一能把
  简报 T1-1（信的骨架）用成「功能」而不是「装饰」的位置。D-A 的全部内容
  （触发条、autosize、草稿）都是 D-B 的子集，施工按 D-B 一次到位，矮视口
  自动获得 D-A 形态。
- **两案叠加后的案头底幕**：`[信流] / [触发条 44px] / [navdock 60px]` =
  移动常驻 104px（现 163px，**-36%**），桌面同构；写作时只剩面板 + 键盘。

### 4.4 需用户豁免 / 显式修订汇总（全部方案的偏离点，一张账）

| # | 偏离点 | 现役条款 | 方案 | 性质 |
|---|---|---|---|---|
| 1 | navdock 加图标 | #18 契约「禁止变体：图标」 | N-A | 契约显式修订 + 用户首验 |
| 2 | 下划线退出导航当前态岗位 | #18 现役 `--on` 形 | N-A/B | 同上（随 1） |
| 3 | 桌面导航迁左岸 | 9.6 断点契约 / 8.2.9 | N-C | 断点契约修订，需裁决 |
| 4 | 写信区「常驻全形」改「触发条常驻」 | 8.2.2 现役 | D-B | 形态级修订，用户首验 |
| 5 | 写作态 = 全页成员（navdock 让位） | ⑩ 登记行新增 | D-B | 宪法登记，非豁免 |
| 6 | 草稿分桶（sessionStorage） | 无现役条款 | D-B | 新行为登记 |
| 7 | 滚动隐现 dock | 「常驻 dock」语义 | D-C | 若采纳需豁免（不推荐） |

**零偏离确认**：三案均不触碰零大圆角（radius ≤2px）、零毛玻璃/发光、阴影两级、
14 色内、图标网格/笔重/文字同行、动效注册表参数、dock ≤5、门厅让位、Esc 退栈、
reduced-motion 双面、`hover:hover` 半区包裹。

## 5. 全面升级机会清单（navdock/dock 之外，按价值排序）

> 体检顺带所见，「能表现更好」的点位；只研究不改码。价值序 = 用户可感收益 ×
> 实现风险的反比。

- **O1 空厅 = 一张待启的白笺（高价值）**：桌面空厅态实测中部 ~500px 全空
  （d0/DD4），只有一行系统小字 + 小图标悬在纸面中央。升级：空厅渲染一张
  微弱稿纸线（`--rule-soft` 1px × `--baseline` 32 周期，高约 3 行）的「白笺」，
  引导句落在笺上，**点笺即开写作态**（D-B 落地后即「点笺提笔」）——空态从
  「读数块的答法」升级为「邀请的手势」。
- **O2 沓容器触屏 sheet 底部越界 8px（bug 级，顺手修）**：实测 sheet bottom
  852 > 视口 844，底部垫层被裁（M3）。贴底算式补 `--safe-bottom` 一项或
  改 `inset` 账。
- **O3 触发条与跨空间动线的最后一公里**：温故「去聊一句」跳案头后停在普通
  案头态，用户还要再点一次输入口。升级：带意图的跨空间跳转在落位后自动开
  写作态（D-B 的 open 带 source 参数）；这是成熟应用「composer deep-link」
  的标准件。
- **O4 最新信词带衰减律（可感性校准）**：39 词全带灰盒连成「碎」感（§2.4）。
  升级方向（P1-2 词表覆盖修复之外的表达侧）：只给**前 N 个未命中过的词**带
  底纹 / 或只在前 5s 内显带后衰减为无（信龄衰减语义现役注释里已有理论
  依据——「可查」随信龄衰减）。需一次真机再验 + 用户首验，非纯参数。
- **O5 主从条可点性无暗示（可发现性）**：who 块整体可点开沓，但视觉上是
  纯文字（M0 顶栏）。升级：名后一枚 20×20 `chevron`（现役图标）+ 沓内封数
  micro 数字（「Nell Alder ⌄ · 2」）——图标契约全合（有文字同行）。
- **O6 寄出后焦点环过重（D4 清账）**：`:focus-visible` 环在程序聚焦后常亮
  （DD6）。升级：写作件焦点环改「左墨线加重 + 纸面微起」的组合（现役 8.2.2②
  语汇），2px 外环只留键盘 Tab 到位路径（`:focus-visible` 的 heuristics 收窄
  或环形重绘为发丝线）。
- **O7 滚动到底死区清账（D6）**：`.flow` 底补 310px 改 `calc(var(
  --navdock-clearance) + var(--dock-trigger-h) + var(--sp-6))`，桌面/移动
  同账（v3-2 令牌账的第一次真实受益者）。任何 dock 方案落地都应顺带此条。
- **O8 信流顶部的「回信在途」灯（等回信形态）**：typing 行现为信流内一行
  弱字（app.js `.typing`）。升级：触发条右侧小字（§3.2 Q7）+ 信流内保留
  首次出现的执笔小图行（`write` 图标现役锚位）——等待态在家具上可见，不在
  信流里重复刷行。
- **O9 门厅封面首绘后的「拆开」余韵**：封面信按钮是文字链（DD1）。升级空间：
  拆开动作 = 邮票角标微旋（现役痕迹随机化语族）+ 封面信整体 paper-unfold
  转场入案头——「拆封」是一次性演出（简报禁的是常规化拆信演出，门厅每次
  进门是「进门」不是「拆信」，需裁：首封后改为直落）。低优先，纯氛围。
- **O10 观察仪表/原始读数页的 mono 账页气质**（低优先）：数据页已是 mono +
  tabular-nums；可补一张「邮戳日戳」规律（归档开启戳现役已有）到仪表空态，
  防止数据页成为全应用唯一「无纸感」角落。谨慎：T2 预算（每屏 ≤1 戳）。
